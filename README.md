## 🛡️ Cybersecurity

[#-cybersecurity](#-cybersecurity)

> [!NOTE]
> Just getting started here — this section is reserved to grow. The goal isn't to become a pentester; it's to bring a real attacker's-eye view into the full-stack systems I already build.

### 🔓 Cyber Lab — Vulnerable Login Lab

[![Repository](https://img.shields.io/badge/View_Repository-181717?style=flat-square&logo=github&logoColor=white)](https://github.com/GabrielJalmeida/cyber.vulnerable-login-lab)

An intentionally vulnerable Flask login lab for learning HTTP requests, Windows↔Kali networking and controlled Medusa testing — with authentication exercises across **web, FTP and SMB** services.

- 🖥️ Custom Flask login form (no rate limiting, lockout or CAPTCHA) analyzed via DevTools, then brute-forced with Medusa in an isolated Host-Only network
- 📡 FTP and SMB service auditing with **Nmap**, **enum4linux** and **smbclient** against an authorized lab target
- ✅ Automated `pytest` suite covering the vulnerable baseline
- 🛡️ A `hardened/` counterpart is already scaffolded — next step is a defensive, tested version to compare side-by-side with the vulnerable one

`Python` `Flask` `Pytest` `Medusa` `Nmap` `Kali Linux` `VirtualBox`

> [!CAUTION]
> Educational lab only. All testing runs inside an isolated, Host-Only/Internal virtual network against systems I own or am explicitly authorized to test — never against real or third-party targets.

## 💡 How I Approach Development

```
Understand the problem
        ↓
Break it into smaller problems
        ↓
Research what I don't know
        ↓
Choose the right tools
        ↓
Build
        ↓
Test
        ↓
Improve
```

I value **learning ability over memorizing tools**. If a project requires something I haven't used before, my first reaction isn't *"I don't know how to do that."* It's:

**"What do I need to learn to make this work?"**
